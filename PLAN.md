# yt-music-analyzer

Локальное web-приложение для анализа музыкальных вкусов на основе истории просмотров YouTube.

## Концепция

Пользователь слушает музыку только на YouTube. Приложение принимает экспорт истории из Google Takeout, отфильтровывает музыкальные треки, извлекает акустические характеристики через открытые ML-модели и предоставляет:

- **Статистику и вкусы** — топ исполнителей/треков, время прослушивания, динамика
- **Плейлисты по настроению** — автоматическая кластеризация треков
- **Рекомендации** — похожие треки и новые исполнители

## Стек

| Слой | Технологии |
|---|---|
| Backend | Python 3.12 (uv), FastAPI |
| БД | SQLite (SQLModel) |
| Frontend | React + TypeScript (Vite), shadcn/ui + Tailwind CSS, TanStack Query, Recharts (SPA, раздаётся FastAPI) |
| Аудио-фичи | librosa (темп, энергия, танцевальность), Essentia (настроение, жанр — предобученные нейромодели) |
| Загрузка аудио | yt-dlp (низкий битрейт, кэш) |
| Кластеризация | scikit-learn (k-means, nearest neighbors) |
| Внешние API | YouTube Data API v3, MusicBrainz |

## Поток данных

```
watch-history.json → Парсер → SQLite → Фильтр музыки → Аудио-анализ → ML-анализ → UI
   (Google Takeout)  (FastAPI)   (БД)   (YouTube API)  (yt-dlp+librosa+Essentia) (k-means) (браузер)
```

## Архитектура конвейера

### Этап 1. Импорт истории
- Пользователь скачивает архив на takeout.google.com (только «История просмотров YouTube»)
- Загрузка `watch-history.json` через UI приложения
- Парсер извлекает: videoId, название видео, канал, время просмотра
- Дедупликация: одно видео, прослушанное N раз, = N прослушиваний одного трека

### Этап 2. Фильтрация музыки
- История содержит всё подряд — оставляем только музыку
- `videos.list` батчами по 50 ID: категория, длительность, теги
- Критерии: категория Music + длительность 1–10 мин + эвристики по названиям
  («Official Video», «Lyrics», feat. и т.п.)

### Этап 3. Аудио-анализ (фоновый воркер, самый долгий этап)
- yt-dlp скачивает аудио в низком битрейте в кэш `data/audio/`
- librosa: темп (BPM), RMS-энергия, танцевальность, акустичность
- Essentia: настроение (happy/sad/relaxed/aggressive — вероятности), жанр
- Результаты в БД; повторный анализ не требуется, аудио можно удалять
- Прогресс отображается в UI (поллинг `/api/state` из React-приложения)

### Этап 4. Плейлисты по настроению
- Векторы фич каждого трека нормализуются
- k-means группирует похожие треки
- Кластеры получают автоназвания по доминирующему настроению:
  «Энергичное», «Спокойное», «Меланхоличное»...
- Страницы плейлистов со ссылками на YouTube

### Этап 5. Рекомендации
- Похожие треки: nearest neighbors по вектору фич
- Новые исполнители: MusicBrainz API по жанру/тегам

## Модель данных (SQLite)

| Таблица | Поля (основные) |
|---|---|
| `track` | video_id (PK), title, channel, duration, category_id, is_music |
| `listen` | id, track_id (FK), listened_at |
| `audio_features` | track_id (PK/FK), tempo, energy, danceability, acousticness, mood_happy/sad/relaxed/aggressive, genre |
| `cluster` | id, name, centroid |
| `track.cluster_id` | принадлежность кластеру |

## Внешние API: лимиты и цена

### YouTube Data API v3 — бесплатно
| Метод | Стоимость | Лимит |
|---|---|---|
| `videos.list` | 1 ед./вызов | общий пул 10 000 ед./день (до 500 000 треков: батчи по 50 ID) |
| `search.list` | 1 ед./вызов | отдельный бакет: 100 вызовов/день |
| прочие | 1 ед. | общий пул 10 000 ед./день |

Сброс квоты — полночь PT. Ключ хранится в `.env`.

### MusicBrainz API — бесплатно (некоммерческое использование)
- Максимум **1 запрос/сек** — троттлинг в клиенте обязателен, иначе блокировка IP
- Ключ не нужен, обязателен осмысленный User-Agent
- Формат: JSON (`fmt=json`), до 100 результатов на страницу

## Подготовка (ручные шаги)

1. **YouTube API-ключ:** Google Cloud Console → создать проект → включить YouTube Data API v3 → Credentials → API key → положить в `.env`
2. **Google Takeout:** takeout.google.com → выбрать только «История просмотров YouTube» → формат JSON → распаковать

## Замечания

- Frontend — SPA на React: бэкенд отдаёт только JSON (`/api/*`) и собранный бандл из `dist/`. Разработка: `uv run uvicorn app.main:app` + `npm run dev` (Vite-прокси `/api` → :8000); продакшен: `npm run build`, затем uvicorn
- Реализовано на Python 3.14: у Essentia нет wheel для 3.12 (на PyPI только cp36–311 в старых сборках и cp314 в lite-сборке без TF-моделей), поэтому настроения считаются эвристически из librosa-фич; Essentia не используется
- Фильтрация музыки: header «YouTube Музыка» из Takeout помечает трек сразу; остальное — эвристики (VEVO/-Topic каналы, feat./official/lyrics/remix, «артист - трек»); при заданном YOUTUBE_API_KEY неуверенные случаи уточняются через videos.list (категория 10 + длительность 1–10 мин)
- Скачивание аудио работает через датацентровый IP (VPN) благодаря SABR-ветке yt-dlp (PR #13515, `coletdjnz/yt-dlp-dev@feat/youtube/sabr`, закреплена в pyproject): формат `ba[protocol=sabr]` + `formats=duplicate` + `player-client=web` + EJS-скрипты (`yt-dlp-ejs`, рантайм node) + cookies Chrome (`AUDIO_COOKIES_FROM_BROWSER`); локальный POT-сервер (data/tools/bgutil-pot-server) поднимается приложением автоматически. Треки без аудио получают предварительные оценки настроения по метаданным (`audio_features.source='meta'`) и перезаписываются реальными фичами при аудио-анализе
- Аудио-анализ длительный: большие истории обрабатываются батчами, всё кэшируется
- Единственное ручное действие в рутине — периодически скачивать свежий Takeout
- Для личного использования; скачивание аудио формально противоречит ToS YouTube
