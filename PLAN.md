# yt-music-analyzer

Локальное web-приложение для анализа музыкальных вкусов на основе истории просмотров YouTube.

## Концепция

Пользователь слушает музыку только на YouTube. Приложение принимает экспорт истории из Google Takeout, отфильтровывает музыкальные треки, извлекает акустические характеристики через открытые ML-модели и предоставляет:

- **Статистику и вкусы** — топ исполнителей/треков, время прослушивания, динамика
- **Плейлисты по настроению** — автоматическая кластеризация треков
- **Рекомендации** — похожие треки и новые исполнители

## Стек

| Слой | Технологии |
|---|---|
| Backend | Python 3.12 (uv), FastAPI |
| БД | SQLite (SQLModel) |
| Frontend | React + TypeScript (Vite), shadcn/ui + Tailwind CSS, TanStack Query, Recharts (SPA, раздаётся FastAPI) |
| Аудио-фичи | librosa (темп, энергия, танцевальность), YAMNet ONNX (жанры, инструменты, вокал), LRCLIB (тексты) |
| Загрузка аудио | yt-dlp (низкий битрейт, кэш) |
| Кластеризация | scikit-learn (k-means, nearest neighbors) |
| Внешние API | YouTube Data API v3, MusicBrainz |

## Поток данных

```
watch-history.json → Парсер → SQLite → Фильтр музыки → Аудио-анализ → ML-анализ → UI
   (Google Takeout)  (FastAPI)   (БД)   (YouTube API)  (yt-dlp+librosa+YAMNet) (k-means) (браузер)
```

## Архитектура конвейера

### Этап 1. Импорт истории
- Пользователь скачивает архив на takeout.google.com (только «История просмотров YouTube»)
- Загрузка `watch-history.json` через UI приложения
- Парсер извлекает: videoId, название видео, канал, время просмотра
- Дедупликация: одно видео, прослушанное N раз, = N прослушиваний одного трека

### Этап 2. Фильтрация музыки
- История содержит всё подряд — оставляем только музыку
- `videos.list` батчами по 50 ID: категория, длительность, теги
- Критерии: категория Music + эвристики по названиям (компиляции и миксы бывают длинными, но >12 ч — 24/7-радиостримы, не треки)
  («Official Video», «Lyrics», feat. и т.п.)

### Этап 3. Аудио-анализ (фоновый воркер, самый долгий этап)
- yt-dlp скачивает аудио в низком битрейте в кэш `data/audio/`
- Треки ≤5 мин (ANALYZE_FULL_MAX) анализируются целиком, длиннее — первые 180 с
- librosa: темп (BPM, с поправкой октавных ошибок), энергия (дБ-шкала), танцевальность, акустичность, яркость, громкость, динамика
- Фичи v2 (feat_version=2): MFCC-13 (тембр), chroma-12 (гармония), spectral contrast-7, percussive ratio (HPSS на 30-с окне)
- Фичи v3 (feat_version=3): YAMNet (ONNX, AudioSet 521 класс, модель в `data/models/`, автоскачивание) — жанры топ-3, инструменты топ-4, vocal_ratio, mood-скоры
- Результаты в БД; повторный анализ не требуется, аудио можно удалять
- Прогресс отображается в UI (поллинг `/api/state` из React-приложения)

### Этап 4. Плейлисты по настроению
- 8 настроений (Весёлое, Меланхоличное, Спокойное, Энергичное, Эпичное, Тёмное, Романтичное, Атмосферное) — ранговые формулы от фич, тональность ≤35%, подмешивание mood-тегов YAMNet
- k-means на взвешенном векторе v2 (тембр 35% · ритм 25% · гармония 25% · макро 15%) — кластеры по звуковому сходству; только треки с реальным аудио-анализом (`source='audio'`)

### Этап 4b. Тексты песен
- LRCLIB API (без ключа, троттлинг 1 req/s): поиск по artist+title с нормализацией (- Topic/VEVO, скобки-мусор), нечёткий матчинг ≥0.6
- Язык (ru/en/cjk) и сентимент (−1…+1, лексиконы) определяются локально; инструменталы (vocal_ratio < LYRICS_MIN_VOCAL) пропускаются; LYRICS_LIMIT за запуск

### Этап 5. Рекомендации
- Похожие треки: взвешенная евклидова метрика по группам фич — тембр (MFCC) 35% · ритм 25% · гармония (chroma) 25% · макро-характер 15%; вектор трека сглаживается центроидом исполнителя (shrinkage)
- Похожие исполнители: центроиды фич каналов из истории прослушиваний
- Новые исполнители: MusicBrainz API по жанру/тегам

## Модель данных (SQLite)

| Таблица | Поля (основные) |
|---|---|
| `track` | video_id (PK), title, channel, duration, category_id, is_music |
| `listen` | id, track_id (FK), listened_at |
| `audio_features` | track_id (PK/FK), tempo, energy, danceability, acousticness, mood_happy/sad/relaxed/aggressive, genre |
| `cluster` | id, name, centroid |
| `track.cluster_id` | принадлежность кластеру |

## Внешние API: лимиты и цена

### YouTube Data API v3 — бесплатно
| Метод | Стоимость | Лимит |
|---|---|---|
| `videos.list` | 1 ед./вызов | общий пул 10 000 ед./день (до 500 000 треков: батчи по 50 ID) |
| `search.list` | 1 ед./вызов | отдельный бакет: 100 вызовов/день |
| прочие | 1 ед. | общий пул 10 000 ед./день |

Сброс квоты — полночь PT. Ключ хранится в `.env`.

### MusicBrainz API — бесплатно (некоммерческое использование)
- Максимум **1 запрос/сек** — троттлинг в клиенте обязателен, иначе блокировка IP
- Ключ не нужен, обязателен осмысленный User-Agent
- Формат: JSON (`fmt=json`), до 100 результатов на страницу

## Подготовка (ручные шаги)

1. **YouTube API-ключ:** Google Cloud Console → создать проект → включить YouTube Data API v3 → Credentials → API key → положить в `.env`
2. **Google Takeout:** takeout.google.com → выбрать только «История просмотров YouTube» → формат JSON → распаковать

## Замечания

- Frontend — SPA на React: бэкенд отдаёт только JSON (`/api/*`) и собранный бандл из `dist/`. Разработка: `uv run uvicorn app.main:app --reload` + `npm run dev` (Vite-прокси `/api` → :8000); продакшен: `npm run build`, затем uvicorn
- Реализовано на Python 3.14: у Essentia нет wheel для 3.12, поэтому Essentia не используется; вместо неё — YAMNet (ONNX, работает на 3.14) для жанров/инструментов/вокала, настроения — ранговые формулы от librosa-фич + mood-теги YAMNet
- Фильтрация музыки (двухпроходная, `app/services/music_filter.py`): 1) уверенные сигналы — header «YouTube Музыка» из Takeout, VEVO/-Topic каналы, сильные паттерны названий (feat./official/lyrics/remix/album…), «артист - трек» на канале с тем же именем (`artist-channel-dash`), анти-паттерны (техника, разработка, обзоры…); 2) голосование по каналу: доля уверенной музыки ≥80% (≥3 треков) → его неуверенные треки музыка, ≤20% → не музыка. Слабые вердикты (artist-dash, no-signal, channel-*, anti-pattern) переоцениваются при каждом запуске фильтра; ручные (`manual`, кнопки в UI) и API-вердикты неприкосновенны. При заданном YOUTUBE_API_KEY неуверенные случаи уточняются через videos.list (категория 10; длительность не критерий)
- Скачивание аудио работает через датацентровый IP (VPN) благодаря SABR-ветке yt-dlp (PR #13515, `coletdjnz/yt-dlp-dev@feat/youtube/sabr`, закреплена в pyproject): формат `ba[protocol=sabr]` + `formats=duplicate` + `player-client=web` + EJS-скрипты (`yt-dlp-ejs`, рантайм node) + cookies Chrome (`AUDIO_COOKIES_FROM_BROWSER`); локальный POT-сервер (data/tools/bgutil-pot-server) поднимается приложением автоматически
- Аудио-анализ длительный: конвейер из параллельных воркеров (AUDIO_WORKERS, 1–4, по умолчанию 2; главный тред — единственный писатель в БД), ретраи сетевых ошибок (5/15/30 с) и стоп после 10 подряд сетевых ошибок — YouTube троттлит IP; большие истории обрабатываются батчами, всё кэшируется (битый кэш самоочищается)
- Единственное ручное действие в рутине — периодически скачивать свежий Takeout
- Для личного использования; скачивание аудио формально противоречит ToS YouTube
